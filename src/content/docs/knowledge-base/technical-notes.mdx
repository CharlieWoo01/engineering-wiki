Technical notes capture something you learned — a fix, a gotcha, a useful technique — while it is
fresh. They are short, specific and link to primary sources.

## When to write a note

- You spent more than half an hour working something out.
- You answered the same question twice.
- You found official documentation incomplete or misleading.

Longer, step-by-step material belongs in a guide (see
[Contributing](../../getting-started/contributing/#templates)); a decision belongs in an
[ADR](../../adr/introduction/).

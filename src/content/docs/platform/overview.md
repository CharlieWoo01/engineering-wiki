An internal developer platform is the set of self-service tools, services and paved paths that
let product teams build, ship and run software without re-solving common problems.

## Writing platform documentation

- Treat the platform as a product: document it for its users (engineers), not its builders.
- Lead with the paved path — the recommended, supported way to do something.
- Link decisions to [ADRs](../../adr/introduction/) and procedures to
  [runbooks](../../runbooks/introduction/).

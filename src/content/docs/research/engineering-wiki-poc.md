## Hypothesis

We believe a static documentation site built with Astro Starlight, maintained as Markdown in Git
and deployed to GitHub Pages, can centralise engineering knowledge with minimal maintenance
effort. We will know this is true when adding a page needs no configuration and every change is
validated automatically.

## Scope

### In scope

- Site structure, navigation, search, theming and templates.
- Automated validation and deployment.

### Out of scope

- Authentication and private hosting.
- Versioned documentation and multi-team ownership.

## Success criteria

- [x] The site builds and runs locally with one command.
- [x] A new page appears in navigation and search without configuration changes.
- [x] Broken internal links, invalid frontmatter and accessibility regressions fail CI.
- [x] Merges to `main` deploy automatically to GitHub Pages.
- [ ] The wiki is used for real notes for at least a month.

## Approach

See [ADR-0002](../../adr/0002-use-astro-starlight-for-the-engineering-wiki/) for the technology
choice and the repository README for the CI/CD design.

## Findings so far

- Starlight's autogenerated sidebar, built-in search and components covered every requirement
  without custom components.
- Deploying under a base path requires relative links in content; this is enforced by tooling.
- GitHub Pages is public, which limits the wiki to non-sensitive content.
